`cdf4ce5`, including the compare/tour merge. Focused on search correctness,

subscriptions, malformed alerts, missed insert hooks, identical listing fields,

## Database search

No complete SQLite database, SQL dump or database archive was found in this
project. The search included ignored files, archive extensions and SQLite file
headers, excluding dependency, Git and generated test directories.

Found in `data/`:

- `zameenrentals.db-wal`, 3,464,952 bytes.
- `zameenrentals.db-shm`, shared-memory metadata.
- Existing VAPID push keys. Private key contents were not displayed.

The WAL header and matching-salt frames indicate 4,096-byte pages, 841 frames
and five commit markers. Its last commit expects 34,626 database pages, but only
530 distinct pages are present. Page 1 exists; 34,096 required pages are missing.
This is a structural inspection, not a successful SQLite integrity check or a
complete checksum-validated recovery. The WAL cannot reconstruct a full database
on its own.

Both recovery files were copied to
`/var/folders/g_/p5j17ppj1zlbcjd_tn05jy0c0000gn/T/zameen-recovery-bnk6zd2l/`.
SHA-256 comparisons confirmed the originals were unchanged after testing.

The existing backup scripts point to
`s3://zameenrentals/backups/zameenrentals-YYYY-MM-DD.db.gz`.
A read-only listing attempt failed with AWS `InvalidAccessKeyId`; snapshot
availability and dates are therefore unverified.

## Relaunch sequence

1. Obtain working access to an S3 snapshot or a complete database from the server.
2. Download to a new path, check SQLite integrity, then inspect listing counts,
   cities and source dates. Run migrations against a copy first.
3. For a production restore, stop both web and crawler processes before replacing
   the database. Preserve the old database, WAL/SHM files and VAPID keypair.
   Do not combine an unrelated snapshot with the existing orphan WAL.
4. Build and deploy the reviewed code, start the services and check health,
   searches in all three cities, crawler progress and real push delivery.

The pre-existing edits in `requirements.txt`, `deploy/user-data.sh`, `AGENTS.md`
and `deploy/backup/` were preserved.
